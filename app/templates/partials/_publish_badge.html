Jinja gives an imported macro the environment's GLOBALS but not the template CONTEXT. social_publish_badge, has_permission and url_for are globals, so they resolve either way - but `current_user` is not: Flask- Login supplies it through a context processor. Imported without context it is Undefined, and the retry branch below then took down the whole task list with a 500. It only reached that line once a task actually had a failed, retryable publish, which is why it sat unnoticed for months. The viewer is also defaulted defensively, so a future template that forgets `with context` loses the retry button rather than the page. #} {% macro publish_badge(task, show_retry=True) %} {% set viewer = current_user if current_user is defined else None %} {% set b = social_publish_badge(task) %} {% if b %} {{ b.label }} {% if b.permalinks %}{% for l in b.permalinks %}{% endfor %}{% endif %} {% if show_retry and b.retry and has_permission(viewer, 'approve_tasks') %}
{% endif %} {% endif %} {% endmacro %}
